# Робота з кодом

## Запуск

```bash
npm install
npm start          # http://localhost:3700
npm run dev        # те саме з автоперезапуском (node --watch)
npm test           # 45 тестів API на базі в пам'яті
```

Потрібен Node.js ≥ 22.13 — молодші не мають вбудованого `node:sqlite`.
Налаштування — у `.env` (див. таблицю в [README](../README.md)).

Клієнт без збирання: змінив `public/*.js` → перезавантажив сторінку. Сервер підхоплює зміни
лише при перезапуску (`npm run dev` робить це сам). Паки й каталог магазину читаються **при старті**,
тож після зміни `packs/` сервер треба перезапустити.

## Скрипти

| Команда | Що робить |
| --- | --- |
| `node scripts/check-packs.js [id...]` | перевіряє зміст паків (швидко, без мережі) |
| `node scripts/make-icons.js` | перемальовує всі іконки паків |
| `node --env-file=.env scripts/generate-packs.js [id...]` | генерує зміст паків через Gemini |
| `node --env-file=.env scripts/build-wordlist-pack.js <json> <packId> [--split]` | пак зі словника підручника |
| `npm test` | тести API |

## Домовленості в коді

- **Коментарі — лише там, де код не пояснює себе сам**: чому обрано таке рішення, а не що робить рядок.
- **Тексти для людей — українською**, включно з помилками API.
- **Клієнт будує DOM через `h()`**, а не рядками — це і зручніше, і прибирає ризик XSS.
- **Перевірки прав — на сервері.** Сховати кнопку замало: кожен маршрут сам перевіряє власника.
- **Нічого не тягнемо в залежності**, поки можна обійтися вбудованим.

## Як додати нову можливість

1. **Маршрут** у `server.js` поруч зі спорідненими; не забути `auth` і перевірку власника.
2. **Схема** — нова колонка через `addColumn()` у `db.js` (старі бази оновляться самі).
3. **Клієнт** — новий екран у `public/app.js` (або окремий файл, якщо великий: так зроблено
   з магазином, адмінкою і «словом з речення») плюс запис у `routes`.
4. **Стилі** — у відповідну секцію `public/styles.css`.
5. **Тест** у `scripts/test-api.js`: і щасливий шлях, і спроба зробити те саме з чужими даними.
6. **Документація** — оновити відповідний файл у `docs/`.

## Тести

`scripts/test-api.js` сам піднімає сервер з `PIPPO_DB=:memory:` на порту 3799, тож робоча база
не зачіпається. Групи: авторизація, чужі дані, слова, тренування та зернятка, магазин, ліміти ШІ,
адмінка, налаштування.

Пишучи тест на нарахування зерняток, пам'ятай про захист від швидких відповідей: між викликами
`/api/answer` потрібні паузи (~750 мс), інакше сервер навмисно нічого не нарахує.

Чого тести поки не покривають: клієнтську логіку (перевірка відповідей з описками, пошук слова
в реченні, розкладка пар) — це чисті функції з `public/text.js`, їх варто покрити наступними.

## Типові граблі

- **Ліміти ШІ рахуються до виклику Gemini.** Невдала відповідь моделі все одно з'їдає квоту
  користувача — так задумано, інакше повторами можна було б обійти ліміт.
- **`tx()` не приймає `await`** усередині: транзакція синхронна.
- **Пак дня й ціни залежать від дня користувача**, а не від дати сервера.
- **Скасування видалення живе в пам'яті процесу** — перезапуск сервера його стирає.
- **Кеш перекладів для паків** (`packs/.<id>.cache.json`) не містить ручних правок: якщо правив
  готовий пак руками, повторна генерація їх перезапише.
