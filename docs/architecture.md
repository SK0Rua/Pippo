# Архітектура

## Стек і чому саме він

| Шар | Рішення | Чому |
| --- | --- | --- |
| Сервер | Node.js ≥ 22.13 + Express 5 | єдина залежність проєкту |
| База | вбудований `node:sqlite` | не треба ставити СУБД, уся база — один файл |
| Клієнт | чистий JS без збирання | немає етапу білду: змінив файл — оновив сторінку |
| ШІ | Gemini API (безкоштовний рівень) + MyMemory як запасний | контекстний переклад без оплати |

Жодного фреймворку, бандлера чи транспілятора. `npm install` ставить лише Express.

## Файли

```
server.js      HTTP API: маршрути, права доступу, правила гри
db.js          схема SQLite, міграції, транзакції
economy.js     зернятка: нарахування, ліміти, журнал, «день» користувача
packs.js       каталог паків слів, ціни, пак дня
ai.js          звернення до Gemini: розбір слова, пакетний переклад, пошук слів у тексті
packs/         зміст паків (JSON)
scripts/       план паків, генерація, перевірка, іконки, тести API
public/        клієнт
  app.js       роутер, головна, словник, тренування, прогрес
  shop.js      магазин паків і вікно зерняток
  capture.js   «слово з речення», «кілька слів одразу», автопереклад
  admin.js     адмінка
  text.js      нормалізація, перевірка відповідей, пошук слова в реченні
  styles.css   усі стилі
  packs/*.svg  іконки паків
docs/          ця документація

```

`text.js` навмисно окремий: його використовує і браузер, і Node-скрипти перевірки паків.

## Як усе рухається

```
браузер                        сервер                         Gemini
  │  fetch /api/... (cookie)      │                              │
  ├──────────────────────────────►│ auth → перевірка прав        │
  │                               │ SQLite (синхронно)           │
  │                               ├─────────────────────────────►│ лише для карток
  │◄──────────────────────────────┤ JSON                         │
```

Клієнт — SPA на hash-роутингу (`#/dict`, `#/train`, `#/shop`). Сервер віддає статику з `public/`
і JSON з `/api/*`. Стану на сервері між запитами немає, крім бази та двох речей у пам'яті процесу:
лічильника спроб входу й буфера «скасувати видалення» (90 с).

## Правила, які тримає сервер, а не клієнт

Клієнту не можна вірити, тому на сервері:

- **Сесія тренування.** `/api/quiz` створює сесію й запам'ятовує видані слова. Відповідь приймається
  лише на слово з сесії, лише один раз і не частіше ніж приблизно раз на 0.7 с.
- **Підсумок тесту** рахується за записами сесії, а не з тіла запиту.
- **Ціна пака** береться з каталогу; `price` чи `free` у запиті ігноруються.
- **Ліміти зерняток і ШІ** — усі лічильники в базі, «сьогодні» визначається за часовим поясом користувача.

Деталі: [economy.md](economy.md), [api.md](api.md).

## База даних

11 таблиць:

| Таблиця | Що зберігає |
| --- | --- |
| `users` | акаунт, пароль (scrypt), XP, зернятка, серія, часовий пояс, ознака адміна |
| `sessions` | токени входу з терміном дії |
| `decks` | словники; `pack_id` — якщо словник створено з пака |
| `words` | слова: переклад, приклад, транскрипція, поличка Лейтнера, лічильники |
| `activity` | відповіді за день (для серії, цілі й теплової карти) |
| `tests` | завершені тренування |
| `grains` | журнал зерняток, `once_key` для разових нагород |
| `quiz_sessions`, `quiz_items` | що сервер видав у тренуванні і що вже зараховано |
| `ai_usage` | звернення до ШІ (ліміти + аналітика) |
| `user_packs` | куплені паки |

Міграції прості: `addColumn()` додає колонку, якщо її ще немає, а `CREATE TABLE IF NOT EXISTS`
створює нові таблиці. Старі бази оновлюються самі при старті.

## Інтервальне повторення

`INTERVALS = [0, 1, 3, 7, 14, 30]` — дні до наступного показу для поличок 0–5.

- Правильна відповідь переводить слово на наступну поличку **лише якщо його вже пора було повторювати**.
  Інакше можна було б «прокачати» слово за один вечір.
- Помилка відкидає на дві полички назад і ставить слово в чергу на сьогодні.
- Поличка 5 = «вивчено». Найшвидший шлях туди — 25 днів.

## Що знати, працюючи з кодом

- **Запити до SQLite синхронні.** Обробник маршруту без `await` виконується атомарно — саме тому
  покупка пака не має гонок.
- **`tx(fn)`** обгортає зміни в транзакцію; усередині не можна робити `await`.
- **Клієнт будує DOM через `h()`** — рядки не вставляються як HTML, тому XSS через слова неможливий.
- **Після зміни `packs/`** запускай `node scripts/check-packs.js`.
- **Після змін API** — `npm test` (45 сценаріїв, база в пам'яті).
